# 青梧大学 · 大学生存图鉴

一款以校园大世界探索为核心的剧情成长游戏。当前版本包含原生微信小程序与零依赖浏览器预览，两端共用角色、剧情、成长、考试和地图引擎。

## 已实现

- 4 名可选角色，独立初始属性、四种发型设定、人物配色与角色特长（发丝/衣领/高光等细节绘制）
- 人物四向建模：正/背/左/右分别有独立画法（背面是后脑与背包，侧面是单眼、鼻梁与下颌线）
- 2400 × 1600 校园地图，人物行走、点击寻路、建筑碰撞与镜头跟随
- 图书馆、教学楼、实验楼、食堂、宿舍、体育馆、社团中心、青梧湖共 8 大场景
- 每个场景配有专属插画风背景：星空、月亮、书架、黑板、烧瓶气泡、食堂蒸汽、寝室串灯、体育馆跳球、舞台聚光灯、湖畔萤火虫
- 每个场景 2 个可接对话任务，共 16 段原创故事、多选项对话与重复体验收益递减
- 学识、体魄、心态、人缘、实践、精力 6 项状态
- 8 个学期覆盖完整大学四年：每学期 4 周行动 + 1 次期末考，假期恢复精力
- 期末考 5 道情境题（10 题题库，由本局种子码抽取）+ 日常成长计分，学期结算面板
- 随机种子：每局生成 6 位种子码，同一角色 + 同一种子码可复现完全相同的一段四年
- 选择日志：随时翻看做过的选择、所在学期周次与属性变化，关掉后回到打开日志前的地方
- 大四下学期结束后按四年积累进入毕业结局：学术深造、学生领袖、创新实践、温暖人生、未来可期
- **周目继承**：毕业时把本局成绩并入跨周目存档（最高属性 / 结局 / 隐藏事件），下一周目开局可以继承一项遗物（属性、道具、每周精力或全员好感），继承哪一件由玩家在角色页选择
- **隐藏事件**：5 个场景各藏一段只有继承对应遗物才会显形的事件，并带自己的解锁条件（继承遗物 + 完成该场景前置任务），完成后计入隐藏事件进度
- **因果面板**：`choiceLog` 记录每一次选择、当场的影响，以及它几周后引发的连锁后果；右上角「因」随时按学期翻看，还没发作的后果会提前列出来
- GitHub Actions 自动运行核心逻辑、语法与构建检查

## 快速体验

### 浏览器

直接打开 `web/index.html`，或在项目目录运行：

```bash
npm start
```

访问 `http://127.0.0.1:8080`。电脑使用 WASD / 方向键移动、E 互动，也可点击地图寻路；手机使用虚拟摇杆。

### 微信开发者工具

1. 打开微信开发者工具，选择「导入项目」。
2. 目录选择本项目根目录（包含 `project.config.json`）。
3. 测试阶段可使用测试号；正式发布时在 `project.config.json` 替换为团队小程序 AppID。
4. 编译后从角色页进入校园。

## 周目继承与因果面板

**存档继承字段**（`engine/save.js`，浏览器用 `localStorage`，小程序用 `wx storage`）：

```js
{
  playthroughs,   // 已经走完的周目数
  bestStats,      // 四年里各项属性的最好成绩 —— 决定下一周目能继承什么
  endings,        // 见过的结局
  hiddenEvents,   // 解锁过的隐藏事件
  lastEnding,     // 上一局的结局与均分
  lastChoiceLog   // 上一局最后几个选择，用于因果面板的「上一周目回声」
}
```

`GameCore` 的存档（`serialize()`）同样带着 `playthrough / legacyId / legacyEnergyBonus / hiddenCleared / choiceLog`，
所以继承关系和因果记录是跟着存档走的。

**继承选择 UI**：只有 `playthroughs > 0` 时角色页才会出现「周目继承」区块。每件遗物都带解锁条件
（例如「上一周目学识达到 60」「完成过一次毕业」），没达到的卡片置灰并显示差值；一局只能选一样，也可以选「什么都不带」。

**隐藏事件解锁条件**：`HIDDEN_EVENTS[scene][i].requires` 指向一件遗物，`after` 指向该场景里必须先完成的任务。
未满足时任务列表里是一条虚线锁定项，写明解锁条件；满足后才变成可进入的「隐藏事件」。

**choiceLog 写入点**：任务选择（`applyChoice`）、NPC 请求（`resolveRequest`）、连锁后果（`resolveChain`）、
期末考试（`finishExam`）、继承（`applyLegacy`）都会写一条记录。埋下后果时 `consequences` 里记下
`{ eventId, title, fireAt, fired }`，等它真的发作，`collectTriggers()` 会回头把 `fired` 标成 `true`。

**因果面板 UI**：右上角「因」打开，先看属性影响总量与「还没发作的后果」，再按学期倒出时间线，
每条记录显示类型、选择内容、当场影响、好感变化，以及「↳ 3 周后引发『迟到的第三次点名』· 已发作」这类因果链接；
顶部标签可按任务 / 关系 / 后果 / 隐藏 / 学业 / 继承筛选。

## 组员协作

建议按模块分工，减少冲突：

- 剧情同学只改 `miniprogram/data/content.js`。
- 地图与美术同学主要改 `engine/renderer.js`，人物绘制说明见 `角色建模说明.md`，改完打开 `web/sprite-lab.html` 对照。
- 玩法同学改 `engine/core.js` 与 `tests/core.test.js`。
- 小程序交互同学改 `pages/`，浏览器交互同学改 `web/app.js` 与 `web/styles.css`。

每次修改共享引擎或内容后，提交前运行：

```bash
npm test
npm run check
npm run build
```

`web/bundle.js` 由构建脚本生成，不要直接编辑。小程序本身不需要 npm 依赖。

## 首次上传到 GitHub

由仓库负责人在 GitHub 新建空仓库（不要自动生成 README），然后在本目录执行：

```bash
git init
git add .
git commit -m "feat: 青梧大学校园大世界首个可玩版本"
git branch -M main
git remote add origin <团队仓库地址>
git push -u origin main
```

组员随后克隆仓库，基于 `main` 新建功能分支并提交 Pull Request。不要多人直接同时推送到 `main`。
